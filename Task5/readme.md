<h2>Задание 5. Проектирование эволюции MVP в SaaS-платформу</h2>

<p>После успешного внедрения MVP на своих фермах компания собирается вывести решение как коммерческую SaaS-платформу для других агрохолдингов. Это потребует изменений как в архитектуре, так и в бизнес-модели.</p>

<h4>Требования к SaaS-платформе</h4>

<p>Платформа должна:</p>
<ul>
    <li>обеспечивать полную изоляцию данных между клиентами;</li>
    <li>поддерживать гибкую систему подписок с разными тарифными планами;</li>
    <li>предоставлять API для интеграции с системами клиентов (варианты прорабатываются);</li>
    <li>иметь панель самообслуживания для управления аккаунтом (однако пока нет специального интерфейса администратора);</li>
    <li>масштабироваться горизонтально по мере роста числа клиентов;</li>
    <li>собирать метрики использования для аналитики и биллинга.</li>
</ul>
<p>Обратите внимание,что для биллинга и монетизации нужна интеграция с российскими платёжными системами, а для онбординга — документация и API для самостоятельной интеграции.</p>

<h4>Цели бизнеса</h4>
<ul>
    <li>Создать новый источник регулярного дохода.</li>
    <li>Уменьшить TCO для клиентов за счёт облачной модели.</li>
    <li>Ускорить выход на рынок и масштабирование.</li>
    <li>Собрать данные для создания собственных ML-моделей.</li>
</ul>

<h4>Что нужно сделать</h4>

<p>Спроектируйте мультитенантную архитектуру, которая позволит обслуживать несколько клиентов на единой платформе на основе варианта, который был выбран по критериям из Задания 4.</p>

<h5>Задача 1. Проектирование мультитенантной архитектуры</h5>

<ol>
    <li>Создайте новое ADR со ссылкой на основной вариант из Задания 4.
    Проработайте два-три варианта изоляции данных с критериями сравнения (изоляция на уровне схем БД, на уровне отдельных БД и на уровне инстансов).</li>
    <li>Представьте диаграммы C2 (или C3 при необходимости) для каждого варианта.</li>
</ol>

<h5>Задача 2. Разработка системы биллинга и монетизации</h5>

<ol>
    <li>Добавьте сервисы тарификации и биллинга.</li>
    <li>Спроектируйте интеграцию с российскими платёжными системами.</li>
</ol>

<h5>Задача 3. Проработка интеграций с клиентами</h5>

<ol>
    <li>Спроектируйте API для клиентов SaaS-платформы.</li>
    <li>Определите scope доступного функционала.</li>
    <li>Проработайте вариант предоставления документации для интеграции (dev-порталы).</li>
</ol>

<h5>Задача 4. Создание финальной архитектуры To-Be</h5>

<ol>
    <li>Сформируйте C1 и C2 диаграммы финального варианта SaaS-платформы.</li>
    <li>Добавьте C2 диаграмму примера интеграции с текущей компанией как клиентом и ее фермами.</li>
    <li>Включите все схемы в ADR.</li>
</ol>

<h5>В результате у вас должен получиться ADR, где сформированы:</h5>

<ol>
    <li>Диаграммы на уровнях С2 и С3 при необходимости для нескольких вариантов изоляции данных.</li>
    <li>Диаграммы C1 и С2 финального варианта To-Be решения для SaaS-платформы.</li>
    <li>Диаграмма уровня С2 для примера интеграции.</li>
</ol>
